A bitcoin postage packing dashboard should track scale health alongside parcel weight. Treat each check as an auditable event in your shop script or spreadsheet, with a clear pass, fail, or overdue state. Keep this local control separate from label checkout at [Bitcoin Shipping Labels](https://www.bitcoinshippinglabels.com).

Use a reference weight with a documented value and suitable accuracy for the scale and working range. Follow the manufacturer's checking procedure and tolerance; a household object with an assumed weight gives weak evidence. Start on a stable surface, confirm zero, and record the reading in consistent units.

Log the device identity, check date and time, operator, reference weight identity, reference value, observed value, tolerance, and result. Store the original observation rather than overwriting it when someone repeats a check. Link each parcel's weighing event to its scale and timestamp so your dashboard can identify affected work.

If a check fails, mark that device unavailable and hold parcels weighed since its last passing check. Missing check history should also trigger review. Block those parcels from your local bitcoin postage purchase queue until they have been reweighed on a verified scale. Never silently subtract an estimated offset: errors can vary across loads, and a guessed correction hides the underlying fault.

Display an alert with the device, failed check, affected parcel references, and release requirements. Schedule overdue alerts using your documented checking interval. A failed verification may require servicing or calibration; release the device only after it passes the required checks.
